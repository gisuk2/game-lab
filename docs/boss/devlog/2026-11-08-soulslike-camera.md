# 2026-11-08 — "전반적으로 가볍다" 진단 → 3D 채택, 소울류 카메라·락온·구르기

## 피드백

3D 시험판 플레이 후: "맵 전체를 보여주는 느낌, 보스가 웅장하지 않다, 무기 교체가 기계적, 긴장감이 없다, 전반적으로 가볍다."

## 진단

| 원인 | 지금 | 소울류 |
|---|---|---|
| 시점 | 위에서 경기장 전체 → 다 작고 안전해 보임 | 등 뒤 낮은 카메라 → 보스가 화면을 채움 |
| 크기 | 보스 높이 ≈ 플레이어 2배 | 3~10배 |
| 준비 동작 | 무기만 돌아감 | 몸 전체 + 정점에서 멈칫 → 순간 내려침 |
| 이펙트 | 바닥 빨간 판 | 궤적·충격파·균열·먼지·충전 빛·저음·화면 흔들림 |
| 템포 | 기술 하나 → 무기 교체 → 기술 하나 | 한 자세로 2~4개 연계, 결정적 순간에 극적인 형태 변화 |
| 위협 크기 | 범위가 경기장에 비해 작음 | 큰 기술은 공간 지배 |
| 리듬 | 보스가 금방 회복 → 조금씩 계속 때림 | 크게 피함 → 확실한 빈틈 → 크게 반격 |

결론: 이미지 하나의 문제가 아니라 다섯 가지(시점·크기·준비 동작·이펙트·리듬)가 함께 빠져 있음. → 4단계 계획 (계획서 3D-1~4), 결정은 [ADR 0002](../../adr/0002-2d-vs-3d.md)

## 3D-1 구현

| 항목 | 내용 |
|---|---|
| 카메라 | 플레이어 등 뒤 300, 기본 21° 내려다봄. 마우스로 돌림(위아래 6~54°). 화면을 클릭하면 마우스가 잡힘(포인터 잠금), ESC로 풀리면 일시정지 |
| 락온 | Q·휠 클릭. 카메라가 "플레이어 → 보스" 방향으로 부드럽게 돌아가고, 플레이어와 보스 사이를 바라봄. 보스 위에 빨간 원 표시. 너무 멀거나 보스가 쓰러지면 해제 |
| 이동 | 카메라 기준 WASD (W = 화면 앞쪽) |
| 방향 | 공격·구르기: 락온 중 = 보스 쪽 / 아니면 이동 방향 / 가만히 있으면 지금 보는 쪽 (마우스 조준 없음) |
| 구르기 | 대시 → 구르기: 이동 120을 0.4초 동안 (처음 빠르고 끝에서 느림), 0.02~0.32초 무적, 끝 경직 0.15초(이때는 아무것도 못 함). 구르는 중 공격을 누르면 끝 경직 없이 구르기 공격. 내부 이름은 기존 `dash` 유지 |
| C 키 | 경기장 전체 보기 (페이즈 연출 미리보기용으로 남김) |

## 검증 `[검증됨]`

| 검증 | 결과 |
|---|---|
| 타입 검사 | 통과 |
| 테스트 | **161개 통과** (신규: 구르기 2, 카메라 기준 이동·방향 5 / 수정: 구르기 끝 경직에 맞춘 기존 대시 테스트 3) |
| 일부러 망가뜨리기 | 좌우 뒤집힘 / 락온 무시 / 끝 경직 없음 → 모두 잡힘 |
| 헤드리스 실행 | 카메라를 90° 돌린 뒤 W → 오른쪽(+x)으로 이동, S → 반대, D → 아래(+y) 확인. 구르기: 무적·이동 120·감속·스태미나 25 소모 확인. 락온 표시·등 뒤 시점 스크린샷 |
| 테스트 중 발견 | 첫 실험에서 "90° 돈 뒤 W"가 엉뚱한 방향으로 측정됨 → 보스와 몸이 부딪혀 밀린 것. 보스가 멀리 있을 때 다시 측정해 확인 (코드 문제 아님) |
| 테스트 도구 주의 | `-0`과 `0`을 다르게 보는 비교가 있어 숫자 근사 비교로 작성 |
| 미검증 | 실제 마우스 감도·포인터 잠금 느낌 (헤드리스에서는 마우스 잠금이 안 돼 카메라 회전을 함수로 직접 호출해 확인) |
