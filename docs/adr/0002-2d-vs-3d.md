# ADR 0002: 2D(Phaser) vs 3D(Three.js) 화면

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-08 |
| 상태 | **채택: 3D (소울류 3인칭)** — 2D는 프로토타입으로 동결 |

## 배경

- 페이즈 패턴의 "화면이 맵 전체로 전환 → 멈춤 → 헬퍼 설명" 연출은 카메라 방식에 크게 좌우된다 → 페이즈 기믹을 많이 만들기 전에 정한다.
- 로직(플레이어·보스·판정·탄·되감기·효과음)은 처음부터 화면과 분리해 두어서, **어느 쪽을 골라도 로직은 그대로** 쓴다. 바뀌는 것은 화면(View)과 입력뿐.

## 시험판

| 항목 | 2D (index.html) | 3D 시험판 (3d.html) |
|---|---|---|
| 엔진 | Phaser 4 | Three.js r187 |
| 카메라 | 고정 (경기장 전체) | 따라가는 쿼터뷰 / C 키: 경기장 전체 |
| 높이 표현 | 그림자 + 위로 띄움 (가짜 높이) | 실제 높이 + 실제 그림자 |
| 무기 | 선·도형 실루엣 | 단순한 입체 (같은 자세 계산 `weaponPose` 공유) |
| 예고 | 바닥 점선 + 채움 | 바닥 판 + 점선 (원근 때문에 앞뒤로 눌려 보임) |
| 빠진 것 (3D) | | 헬퍼 안내, 사망 지도·기록, 체크포인트 (비교용) |

## 판단 기준 (플레이하면서 확인)

| 기준 | 질문 |
|---|---|
| 읽기 | 무기 실루엣·준비 동작이 어느 쪽에서 더 빨리 읽히나? |
| 공정성 | 한 방 사망에서 "못 봐서 죽었다"가 어느 쪽에서 더 자주 나오나? (3D는 화면 밖·가림 문제) |
| 조작 | 마우스 조준이 원근 화면에서 자연스러운가? |
| 연출 | 페이즈 화면 전환(C 키)이 어느 쪽이 더 인상적인가? 스토리(시뮬레이션) 분위기는? |
| 비용 | 앞으로 만들 기믹 10개·잔상·학습 연출을 어느 쪽이 더 쉽게 만들 수 있나? |

## 시험판에서 관찰한 것 `[검증됨: 스크린샷]` / 판단 `[추정]`

| 관찰 | 의미 |
|---|---|
| 지연 내려찍기: 보스가 머리 위에 떠 있는 동안 몸통이 플레이어 주변을 가림 | 3D의 가림 문제. 카메라를 더 높이거나, 공중의 보스를 반투명하게 하는 보완이 필요 `[추정]` |
| 실제 그림자로 착지 지점·높이가 2D보다 직관적 | 3D의 장점 |
| 따라가기 카메라는 보이는 범위가 좁음 → 멀리서 쏘는 사격·충격파가 화면 밖에서 시작될 수 있음 | 원거리 패턴의 공정성 문제. 2D는 항상 전체가 보임 |
| 경기장 전체 카메라(C)는 2D 화면과 거의 같은 정보량 + 입체감 | "평소엔 2D처럼 전체, 페이즈 때 연출용으로 카메라 이동"도 선택지 `[추정]` |

## 선택지

| 안 | 내용 |
|---|---|
| A. 2D 유지 | 지금까지의 화면을 다듬음. 가장 안전 |
| B. 3D로 전환 | 화면·입력·HUD를 Three.js로 옮김 (로직은 그대로). 가림·화면 밖 문제 보완 필요 |
| C. 3D + 넓은 고정 카메라 | 3D지만 평소엔 경기장 전체가 보이는 카메라, 페이즈 때만 카메라 연출 |

## 결정 (2026-11-08)

**B. 3D로 전환하되, 시점은 소울류 3인칭(등 뒤 카메라 + 락온)으로.**

| 항목 | 결정 |
|---|---|
| 시점 | 플레이어 등 뒤에서 따라가는 카메라, 마우스로 돌림. 시험판의 "위에서 내려다보는 쿼터뷰"는 맵 전체가 보여서 가볍다는 피드백 |
| 락온 | Q + 마우스 휠 클릭. 카메라가 플레이어 뒤에서 보스 쪽을 바라봄 |
| 조작 | 카메라 기준 WASD, 공격은 락온 대상 또는 이동 방향 (마우스 조준 없음) |
| 회피 | 대시 → **구르기** (앞부분 무적, 끝 경직) |
| 미술 | 홀로그램·와이어프레임 (시뮬레이션 설정, 단순 도형이 의도된 스타일로 보임) — 2단계 |
| 2D | 동결. 로직 공유 덕분에 계속 실행은 되지만 새 기능은 3D에만 |

### 결정 이유

- 플레이 피드백: "전반적으로 가볍다". 원인 분석 → 시점·크기·준비 동작·이펙트·리듬 ([devlog](../devlog/2026-11-08-soulslike-camera.md)). 시점과 크기는 3D 3인칭이 아니면 해결이 어려움
- 로직이 화면과 분리되어 있어 전환 비용이 화면·입력에 한정됨

### 감수하는 것

| 위험 | 대응 |
|---|---|
| 등 뒤 카메라는 시야가 좁음 → 뒤·옆 공격, 화면 밖 원거리 공격 | 락온, 소리 신호(조준 고정 틱), 공격 범위·이펙트를 크게 (3단계) |
| 보스가 가까우면 화면을 가림 | 카메라 거리·높이 조정, 2단계에서 보스 크기와 함께 맞춤 |
| 바닥 예고는 낮은 시점에서 잘 안 보임 | 원래 방향대로 몸짓·이펙트 중심, 바닥 예고는 1막 보조 표시로 약하게 |
