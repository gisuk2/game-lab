# 2026-11-08 — 3D 시험판 (Three.js)

## 목표

2D와 3D 중 어느 쪽으로 갈지 정하기 위해, **같은 로직**을 3D 쿼터뷰로 띄워 비교한다. → [ADR 0002](../adr/0002-2d-vs-3d.md)

## 구현

| 파일 | 역할 |
|---|---|
| `3d.html` | 3D 시험판 페이지 (`/3d.html`). 2D 버전으로 가는 링크 |
| `src/three/main3d.ts` | 진입점 |
| `src/three/Game3D.ts` | 게임 루프 (2D GameScene과 같은 순서, 같은 모델·판정·탄·되감기·효과음) |
| `src/three/World3D.ts` | Three.js 화면: 바닥·격자·벽, 플레이어(원기둥+검), 보스(육각기둥+무기 6종), 바닥 예고, 탄·충격파, 그림자, 카메라(따라가기 / 경기장 전체) |
| `src/three/DomInput.ts` | 키보드·마우스 (Phaser 없이). 마우스 조준 = 화면 좌표 → 바닥 위 점 |
| `src/entities/boss/weaponPose.ts` | **보스 무기 자세 계산을 2D 화면에서 분리** → 2D·3D가 같은 자세를 씀 (2D 동작은 그대로) |
| `vite.config.ts` | 빌드 시 페이지 두 개 (Vite 8: `rolldownOptions`, 공식 문서로 확인) |

## 설치 (사용자)

`npm install three` / `npm install -D @types/three` (three 0.187.0)

## 검증 방법의 한계와 우회

| 문제 | 우회 |
|---|---|
| 작업 환경과 사용자 컴퓨터의 작업용 가상 환경 모두 npm 네트워크 차단 | 사용자가 설치 → 설치된 three·타입 파일을 압축해 가져와 이쪽에서 타입 검사 |
| 프로젝트의 TypeScript 7은 Windows 전용 실행 파일이라 가상 환경에서 실행 불가 | 작업 환경의 같은 버전(7.0.2)으로 검사 |
| 게임을 직접 볼 수 없음 | esbuild로 묶어서 headless Chrome(소프트웨어 WebGL)에서 실행 → 스크린샷, 키·마우스 입력 흉내 |

## 화면 확인에서 발견·수정

| 발견 | 수정 |
|---|---|
| 콘솔 경고: `PCFSoftShadowMap`이 r187에서 제거됨 | `PCFShadowMap`으로 |
| 콘솔 경고: 사용자 입력 전에 소리 장치를 만들려 함 (**2D에도 해당**) | 첫 키·클릭 전에는 소리를 내지 않도록 |
| 따라가기 카메라가 경기장 밖을 많이 비추고, 아래 벽이 보스 체력 바와 겹침 | 바라보는 점을 경기장 안쪽으로 제한, 체력 바에 흰 배경 |

## 검증 `[검증됨]`

| 검증 | 결과 |
|---|---|
| 타입 검사 (three 타입 포함) | 통과 |
| 테스트 | **155개 통과** (신규: 무기 자세 3) |
| 일부러 망가뜨리기 | 붉은 빛 안 남 / 연속 베기 좌우 고정 → 각각 잡힘 |
| 3D 실행 | headless Chrome에서 실행, 오류 없음. 스크린샷: 시작, 잡기 예고, 경기장 전체 카메라, 지연 내려찍기 체공·착지·사망·재시도 감소 |
| 미검증 | 실제 GPU에서의 속도·느낌, 마우스 조준 감각 → 사용자 플레이 |
